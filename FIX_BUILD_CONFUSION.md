# Инструкция для ИИ-исполнителя: почему сборка v5 падает и что делать

## Суть проблемы (не в коде)

В репозитории, похоже, оказались перемешаны ДВЕ разные папки:
- `xi-notes/` — это ЕДИНСТВЕННЫЙ настоящий, актуальный проект. Именно в нём лежит
  вся текущая функциональность (чек-листы, напоминания на пункты, файлы-вложения,
  восстановление последней заметки и т.д.) — то, что называется "v5".
- `xi-notes-v4/` (или похожий путь вроде `Ξ-notes/xi-notes-v4/...`) — это ОТДЕЛЬНАЯ,
  временная, урезанная копия, которую я собирал один раз специально для диагностики
  старого краша (без чек-листов, без файлов-вложений, без части фич). Она НЕ является
  следующей версией проекта и не должна участвовать в дальнейшей разработке вообще.

Отсюда и ошибка: если ты (или предыдущий запуск) пытаешься собрать
`.../xi-notes-v4/app/build.gradle.kts`, думая что это "v5" — ты собираешь СТАРУЮ,
урезанную, тупиковую ветку. Она не содержит новых файлов (`ChecklistParser.kt`,
`FileStore.kt` и т.д.), поэтому сборка либо падает, либо получается не той версией,
которую тестирует пользователь.

## Что сделать прямо сейчас

1. **Удали папку `xi-notes-v4` (и любые её следы) из репозитория полностью.** Она
   больше не нужна ни для чего.
2. **Работай только с содержимым папки `xi-notes/`** из этого архива — это и есть
   актуальная v5. Путь к файлу сборки: `xi-notes/app/build.gradle.kts` (НЕ
   `xi-notes/xi-notes-v4/app/build.gradle.kts` и не любой другой вложенный путь).
3. Распакуй содержимое ЭТОГО архива поверх репозитория, заменяя всё целиком (это
   самая свежая версия — с подсветкой пунктов чек-листа, файлами-вложениями,
   динамическими напоминаниями и восстановлением последней заметки).
4. Закоммить, запушь, дай GitHub Actions собрать `app/build/outputs/apk/debug/app-debug.apk`
   заново — уже из правильной, единственной папки `xi-notes/`.
5. Если сборка всё равно упадёт — присылай именно текст ошибки от Gradle/Kotlin
   (строки, начинающиеся с `e:` или `FAILURE: Build failed`) — это единственное, что
   реально помогает найти причину, а не гадание по путям.

## Проверено статически перед отправкой этого архива
- Все `.kt` файлы в `xi-notes/` — парность скобок `{}`/`()` сходится везде.
- Все `.xml` (манифест, `file_paths.xml`, ресурсы) — валидны.
- Метод/модификатор `.weight(...)` используется только там, где корректно
  импортирован `androidx.compose.foundation.layout.weight` — несовпадений нет.
