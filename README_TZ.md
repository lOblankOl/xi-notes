# Ξ-notes — техническое задание для реализации Android-приложения

> Этот документ адресован ИИ-агенту, который имеет доступ к GitHub и файлам на ноутбуке пользователя и должен реализовать приложение полностью самостоятельно, шаг за шагом, коммитами в репозиторий. Ниже — исчерпывающая спецификация. Не додумывай требования — если что-то не описано явно, выбирай самый простой и лёгкий по ресурсам вариант.

## 1. Что за приложение

Название: **Ξ-notes** (символ Ξ — заглавная греческая "кси").
Платформа: **только Android** (телефон, не планшет-специфично).
Тип: локальный блокнот для заметок. **Никакого облака, никакой синхронизации, никаких сетевых разрешений вообще** — приложению не нужен доступ в интернет.

Контент заметки: текст + опционально вставленные изображения (из галереи или с камеры). Форматирование текста — не нужно (никакого rich text/markdown-рендеринга), просто обычный текст с возможностью вставки картинок между абзацами.

## 2. Технологический стек (обязательно)

- **Kotlin + Jetpack Compose** (не Flutter). Причина: нативный стек даёт значительно меньший расход RAM и батареи на простом CRUD-приложении, чем Flutter-рантайм — а это здесь главный приоритет.
- Локальная БД: **Room** (SQLite) — таблицы `notes` и `note_images`.
- Изображения хранить как файлы во внутреннем хранилище приложения (`context.filesDir/images/`), в БД — только пути/имена файлов, не blob.
- Напоминания: **AlarmManager** (`setExactAndAllowWhileIdle`) + `BroadcastReceiver` + обычное системное уведомление (heads-up), без Firebase/облачных push.
- Минимальный `minSdk` — 26 (Android 8.0), `targetSdk` — актуальный на момент сборки.
- Никаких сторонних тяжёлых библиотек без необходимости. Никакой аналитики, никакой рекламы, никаких сетевых SDK.

## 3. Структура и навигация

### 3.1 Главный экран
Открытая заметка на весь экран — большое текстовое поле, редактируемое сразу (без отдельного режима "просмотр/редактирование").

### 3.2 Боковая панель (side drawer)
- Открывается двумя способами: свайпом от левого края экрана **и** кнопкой-гамбургером (иконка "три полоски" ☰) в левом верхнем углу шапки — стандартное поведение, тап по кнопке открывает/закрывает панель так же, как свайп.
- Панель чётко разделена на **две секции** (это важно — не смешивать в одном списке):

  **Секция 1 — "Напоминания"** (сверху, показывается только если есть хоть одна заметка с активным напоминанием):
  - Список заметок, у которых стоит напоминание, отсортированный по ближайшему времени.
  - У каждой строки — время/дата напоминания и заголовок заметки.
  - Визуально отделена от секции заметок (заголовок-разделитель "Напоминания", более тонкий/приглушённый фон, либо небольшая иконка будильника слева от каждой строки).

  **Секция 2 — "Заметки"** (ниже, всегда видна):
  - Заголовок-разделитель "Заметки".
  - Заметки организованы по **группам** (папкам), которые создаёт сам пользователь — см. раздел 3.3.
  - Внутри группы — название заметки (задаётся пользователем, редактируется в любой момент — см. раздел 3.5) + дата последнего изменения, в компактных строках.
  - Тап по заметке — открывает её на главном экране, панель закрывается.
  - Свайп заметки в списке влево — удалить (с подтверждением).
  - Долгое нажатие на заметку — контекстное меню: переименовать/закрепить сверху/переместить в группу/убрать из группы.

- Кнопка "+" вверху панели (над обеими секциями) — создать новую заметку.
- Заметка с активным напоминанием при этом остаётся видна и во второй секции ("Заметки") — секция "Напоминания" это просто быстрый фильтр сверху, не отдельное хранилище данных.

### 3.3 Группы заметок (папки)
- Пользователь может создавать свои группы (например "Школа", "Работа") с произвольным названием.
- Группы отображаются в секции "Заметки" как сворачиваемые (collapsible) блоки — тап по заголовку группы сворачивает/разворачивает список заметок внутри неё.
- Заметки без группы лежат в отдельном псевдо-разделе "Без группы" (всегда снизу или сверху, но не смешиваются визуально с сгруппированными).
- Управление группами:
  - Создать группу — кнопка "+" рядом с заголовком "Заметки" или пункт в контекстном меню.
  - Удалить группу — сама группа удаляется, но заметки внутри **не удаляются**, они переходят в "Без группы" (важно: удаление группы не должно удалять контент).
  - Переименовать группу — долгое нажатие на заголовок группы.
  - Перемещать заметку между группами (в т.ч. в "Без группы") — через контекстное меню заметки (долгое нажатие → "переместить в группу" → выбор из списка групп).
- Заметка может состоять только в одной группе одновременно (без вложенных/множественных групп — это усложнение, которое не нужно).

### 3.4 Перетаскивание заметок (drag-and-drop, ручная сортировка)
- Внутри секции "Заметки" (и внутри каждой группы, и в "Без группы" отдельно) пользователь должен уметь **зажать заметку и перетащить её вверх/вниз**, меняя порядок вручную.
- Реализация: `LazyColumn` + drag-обработчик по долгому нажатию (например через `pointerInput`/`detectDragGesturesAfterLongPress`, либо готовая лёгкая библиотека реордеринга для Compose типа `reorderable` — на усмотрение исполнителя, лишь бы не тянула тяжёлых зависимостей).
- Во время перетаскивания — приподнятая заметка визуально "летит" за пальцем (тень/увеличенный z-index), остальные плавно уступают место.
- Новый порядок сохраняется в БД сразу после отпускания (поле `sort_order`, см. раздел 7).
- Секция "Напоминания" сверху — сортируется автоматически по времени напоминания, её вручную перетаскивать не нужно.

### 3.5 Название заметки
- У каждой заметки есть собственное **название**, которое задаёт сам пользователь — точно так же, как название группы.
- По умолчанию у новой заметки название "Новая заметка".
- Название редактируется в любой момент: поле для названия — прямо вверху экрана заметки (над текстом, крупным шрифтом, как заголовок), а также через пункт "Переименовать" в контекстном меню заметки в боковой панели (по аналогии с переименованием группы).
- Название **не** вычисляется автоматически из текста заметки — это отдельное, независимое поле.

## 4. Напоминания
- В шапке экрана заметки — иконка "будильник".
- Тап — открывает сначала системный **date picker** (выбор конкретного дня, не только сегодня), затем сразу **time picker** (выбор часа/минуты). Напоминание — полноценно календарное: год/месяц/день + время, а не просто "во столько-то сегодня".
- Одно активное напоминание на заметку достаточно (не список из нескольких).

### 4.1 Напоминания на отдельные пункты чек-листа
Помимо напоминания на всю заметку, у **каждого отдельного пункта чек-листа** тоже может быть своё собственное напоминание — независимое от общего напоминания заметки.
- Маленькая иконка будильника у каждой строки чек-листа (рядом с крестиком удаления).
- Тап, если напоминание не стоит — открывает тот же date+time picker; если уже стоит — снимает его.
- Технически: у пункта появляется стабильный числовой `itemId` (назначается один раз, хранится прямо в тексте заметки вместе с временем напоминания), используется как отдельный идентификатор для `AlarmManager`/уведомления — так пункты не мешают друг другу и не путаются с напоминанием всей заметки.
- Такие напоминания тоже показываются в секции "Напоминания" в боковой панели вперемешку с напоминаниями целых заметок (отсортированы по общему ближайшему времени), с пометкой "· пункт списка", чтобы отличать от напоминания всей заметки.
- Напоминания на произвольный кусок обычного текста (не чек-листа) пока не реализованы — для текста используется общее напоминание заметки; выделение произвольных фрагментов текста для индивидуальных напоминаний требует более крупной переработки модели данных и оставлено на будущее.

### 4.1 Поведение уведомления (важно — должно быть строго как в Telegram)
- Создать `NotificationChannel` с `IMPORTANCE_HIGH` — это обязательное условие, иначе уведомление будет тихим и не всплывёт поверх экрана.
- Благодаря `IMPORTANCE_HIGH` система сама покажет его как **heads-up**: всплывает сверху экрана поверх текущего приложения (или на заблокированном экране), со звуком/вибро по умолчанию системы.
- В самом уведомлении: заголовок заметки, короткий превью текста (первая строка), иконка приложения (зелёный шестигранник с Ξ).
- **Смахнуть уведомление** — просто закрывает его, ничего не открывая (это поведение системы "из коробки", отдельно кодировать не нужно, только не ставить `setOngoing(true)`).
- **Тап по уведомлению** — открывает приложение сразу на нужной заметке (через `PendingIntent` с deep-link/extra `noteId`), как если бы пользователь выбрал её из панели.
- Не использовать full-screen intent (это агрессивный формат для будильников/звонков) — обычного heads-up через `IMPORTANCE_HIGH` достаточно и он ведёт себя ровно как уведомления Telegram.

## 5. Дизайн

### 5.1 Общее ощущение
Смесь: тёмно-зелёная тема Telegram + палитра редактора **Atom** (тёмный фон, разные оттенки зелёного для акцентов/подсветки). Минимализм, никаких лишних элементов, всё должно быть предельно "по делу".

### 5.2 Палитра (отправная точка, можно варьировать оттенки в этих пределах)
- Фон основной: `#0D1F1A` (почти чёрный с зелёным подтоном)
- Фон панели/карточек: `#132A22`
- Акцент/активные элементы: `#4CAF7D` (мягкий зелёный)
- Акцент вторичный/подсветка: `#8BC34A` (более светлый зелёный, как syntax-highlight в Atom)
- Текст основной: `#E8F5EE`
- Текст вторичный (даты, плейсхолдеры): `#6E9081`

### 5.3 Иконка приложения
Зелёный шестигранник (hexagon) на прозрачном/тёмном фоне, в центре — символ **Ξ** белым или светло-зелёным. Сделать в виде adaptive icon (foreground/background слои).

### 5.4 Типографика
Системный шрифт по умолчанию (Roboto) — не грузить кастомные шрифты, чтобы не раздувать APK и не тратить лишнюю память.

## 6. Требования к производительности (это главный приоритет)

- Минимальный APK-размер: избегать лишних зависимостей.
- Холодный старт — как можно быстрее (не грузить ничего лишнего при запуске, ленивая загрузка списка заметок).
- В простое (заметка открыта, но не редактируется) — приложение не должно держать активных фоновых процессов, кроме уже запланированных AlarmManager-напоминаний.
- Изображения в заметках — грузить с уменьшением/сжатием (subsampling) под размер экрана, не держать полноразмерные битмапы в памяти.
- Автосохранение текста — с debounce (например, через 1–2 секунды после паузы в наборе), а не на каждое нажатие клавиши.

## 7. Хранение данных — детали схемы

```
Table: groups
  id: Long (PK, autoincrement)
  name: String
  created_at: Long (epoch millis)

Table: notes
  id: Long (PK, autoincrement)
  title: String        -- название заметки, задаётся пользователем вручную (по умолчанию
                          "Новая заметка"), редактируется в любой момент так же, как и
                          название группы; НЕ вычисляется из текста автоматически
  content: String       -- весь текст заметки; изображения обозначаются
                          спецмаркером в тексте, например [[img:filename.jpg]],
                          чтобы порядок текста и картинок сохранялся
  created_at: Long (epoch millis)
  updated_at: Long (epoch millis)
  reminder_at: Long? (epoch millis, nullable)
  pinned: Boolean (default false)
  group_id: Long? (FK -> groups.id, nullable — null значит "Без группы")
  sort_order: Int (ручной порядок внутри группы/"Без группы", меняется при drag-and-drop)

Изображения физически лежат в filesDir/images/<uuid>.jpg,
ссылка на них — через маркер [[img:<uuid>.jpg]] прямо в тексте content.
```

### 7.1 Важно: только внутреннее хранилище приложения
Всё — и база Room, и папка с картинками `filesDir/images/` — должно лежать **строго во внутреннем приватном хранилище приложения** (`context.filesDir`, `context.getDatabasePath(...)`), а не на внешнем/общем хранилище (`getExternalFilesDir`, `MediaStore`, SD-карта и т.п.).

Это даёт то, что нужно: при удалении приложения с телефона Android автоматически стирает всю папку приложения целиком — база данных, все картинки, всё содержимое. Никакого мусора после удаления, никакой ручной очистки писать не нужно — это штатное поведение системы для внутреннего хранилища, просто важно не отклоняться от него и не писать что-либо во внешние/общие директории.

## 8. Разрешения (AndroidManifest)
Только необходимые:
- `POST_NOTIFICATIONS` (для напоминаний, Android 13+)
- `SCHEDULE_EXACT_ALARM` или `USE_EXACT_ALARM` (для точных напоминаний)
- Доступ к галерее — через `ActivityResultContracts.PickVisualMedia` (не требует runtime-разрешения на современных Android) или `READ_MEDIA_IMAGES` как fallback для старых версий.
- Камера — `CAMERA`, только если решишь добавлять съёмку прямо из приложения (иначе не добавляй это разрешение вообще).
- **Никакого** `INTERNET`.

## 9. Порядок работы (для тебя, ИИ-исполнителя)

1. Создать новый Android-проект (Kotlin + Jetpack Compose, minSdk 26) в отдельном репозитории/папке `xi-notes`.
2. Настроить Room: сущность `Note`, DAO, БД.
3. Экран списка заметок (боковая панель) на Compose + `ModalNavigationDrawer` или кастомный swipe-drawer, с секциями "Напоминания"/"Заметки" и сворачиваемыми группами внутри "Заметки" (см. разделы 3.2–3.3).
4. Экран редактирования заметки: `TextField` во весь экран + inline-вставка картинок по спецмаркеру.
5. Вставка изображений: кнопка в тулбаре заметки → выбор из галереи → копирование файла в `filesDir/images/` → вставка маркера в текст в позиции курсора → рендер миниатюры инлайн в Compose (через кастомный `InlineTextContent` или список сегментов текст/картинка).
6. Напоминания: иконка будильника → time/date picker → `AlarmManager.setExactAndAllowWhileIdle` → `BroadcastReceiver` → `NotificationCompat` уведомление с deep-link на заметку.
7. Применить цветовую тему (см. раздел 5) через Material 3 `ColorScheme`.
8. Сделать иконку приложения (adaptive icon, зелёный шестигранник + Ξ).
9. Настроить сборку APK через GitHub Actions (по аналогии с уже существующим пайплайном в проекте Xi-мессенджера, если он есть в этом же аккаунте/организации — переиспользовать рабочий gradle/actions конфиг оттуда как основу).
10. Прогнать сборку, убедиться, что APK ставится и работает на Android 15 (модель для теста — Samsung S25 FE), особое внимание — permissions для уведомлений и точных будильников на новых версиях Android.

## 11. Итоговая поставка — обычный APK-инсталлятор

Результатом сборки (GitHub Actions artifact / Release) должен быть **один готовый файл `xi-notes.apk`**, подписанный debug- или release-ключом (для личного использования без публикации в Play Store достаточно debug-подписи или самоподписанного release-ключа — главное, чтобы APK был не "debuggable" в релизной сборке, чтобы работал плавно).

Как это будет выглядеть у пользователя: скачал `xi-notes.apk` на телефон → тапнул по файлу → система Android сама предложит стандартный диалог "Установить" (может потребоваться один раз разрешить "Установка из неизвестных источников" для того приложения, через которое скачан файл — браузер/файловый менеджер) → тап "Установить" → приложение появляется на рабочем столе как обычное. Публикация в Google Play не нужна и не предполагается.

## 10. Что явно НЕ делать
- Не добавлять облачную синхронизацию, аккаунты, бэкапы в интернет.
- Не использовать Flutter или другие кроссплатформенные фреймворки.
- Не добавлять rich-text/markdown форматирование.
- Не добавлять аналитику, рекламу, любые сторонние SDK с телеметрией.
- Не грузить кастомные шрифты и тяжёлые библиотеки изображений — использовать штатный `Coil` (лёгкая, уже де-факто стандарт для Compose) в минимальной конфигурации.

## 12. Вложение файлов (не только картинки)

Кнопка вставки в тулбаре заметки объединена в одну "+" — тап открывает меню из двух пунктов:
- **"Фото / видео"** — системный медиа-пикер; картинка вставляется как раньше (превью инлайн),
  видео и всё остальное — как файл-вложение (см. ниже), без попытки декодировать/проигрывать
  внутри приложения.
- **"Файл"** — системный выбор любого файла (`OpenDocument`, тип "*/*"), например .apk, документы.

Файл-вложение отображается строкой с иконкой файла и его именем — тап открывает файл системным
приложением (через `FileProvider`), точно так же, как в Telegram: тапнул по .apk — открылся
установщик, тапнул по .pdf — открылся просмотрщик PDF и т.д. Крестик у строки удаляет вложение
из заметки и физический файл с диска.

Хранение — так же, строго во внутренней приватной папке приложения (`filesDir/attachments`),
поэтому удаление приложения стирает все вложения автоматически, как и картинки.

## 13. Восстановление последней открытой заметки

При повторном открытии приложения автоматически открывается та же заметка, что была открыта
при последнем выходе — как в большинстве приложений с вкладками. Хранится это как один-
единственный ключ в `SharedPreferences` (id последней открытой заметки), который просто
перезаписывается при каждом переключении — никакой истории/журнала, значит и накопления
"кэша" от этого не возникает.

## 14. Динамический текст напоминаний

Текст, который показывает уведомление-напоминание, теперь читается заново из базы данных
именно в момент срабатывания, а не запоминается на момент, когда напоминание было
поставлено. Если между установкой напоминания и его срабатыванием пользователь отредактировал
заметку (или конкретный пункт чек-листа) — придёт актуальный, свежий текст, а не старый.
