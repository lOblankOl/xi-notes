# Инструкция для ИИ-исполнителя (читать первым)

Это не просто ТЗ — в этом архиве лежит уже написанный рабочий исходный код Android-приложения
Ξ-notes (Kotlin + Jetpack Compose + Room). Твоя задача — не писать логику с нуля, а:

## Что делать по шагам

1. **Распакуй архив как есть** в новый (или существующий пустой) git-репозиторий с именем
   `xi-notes`. Структура папок уже правильная (`app/src/main/java/com/xinotes/app/...`),
   ничего не переименовывай и не перекладывай.

2. **Закоммить и запушь в ветку `main`** на GitHub. В репозитории уже лежит workflow
   `.github/workflows/build.yml` — он сам соберёт debug-APK при каждом пуше в `main` (либо
   можно запустить вручную через "Run workflow" на вкладке Actions).

3. **Собери проект.** Если у тебя есть локальный доступ к Android SDK — можно собрать и
   локально (`./gradlew assembleDebug`, при первом запуске сначала `gradle wrapper`, т.к.
   бинарник `gradle-wrapper.jar` не входит в архив — это не текстовый файл). Если нет — просто
   полагайся на GitHub Actions, он это сделает сам, включая скачивание Gradle-обёртки.

4. **Если сборка упадёт с ошибкой компиляции** — это ожидаемо: код написан "с чистого листа"
   без доступа к реальному Android SDK для проверки, поэтому возможны мелкие несостыковки
   версий зависимостей или синтаксиса. В таком случае:
   - прочитай текст ошибки от Gradle/Kotlin-компилятора,
   - поправь конкретное место (чаще всего это версии зависимостей в `app/build.gradle.kts`
     или небольшая синтаксическая правка в одном файле),
   - пересобери. Общая архитектура и вся бизнес-логика (см. `Ξ-notes_ТЗ.md`) менять не нужно —
     там всё уже продумано, требуются только технические правки уровня "не собралось".

5. **Готовый файл** — `app/build/outputs/apk/debug/app-debug.apk` (или артефакт `xi-notes-apk`
   на вкладке Actions после сборки в CI). Это и есть финальный инсталлятор — пользователь
   скачивает его на телефон и ставит обычным тапом (подробности — раздел 11 в
   `Ξ-notes_ТЗ.md`).

## Что где лежит

- `Ξ-notes_ТЗ.md` — полное техническое задание с обоснованием всех решений (дизайн, структура,
  UX) — читать для понимания "зачем", если что-то непонятно в коде.
- `app/src/main/java/com/xinotes/app/` — весь исходный код:
  - `data/` — Room: сущности `Note`, `NoteGroup`, DAO, база, репозиторий.
  - `reminder/` — напоминания: планировщик через `AlarmManager`, `BroadcastReceiver`,
    heads-up уведомление (канал `IMPORTANCE_HIGH`, ведёт себя как в Telegram).
  - `util/ImageStore.kt` — импорт и хранение картинок только во внутренней памяти приложения.
  - `ui/` — экраны на Compose: `MainScreen` (шапка с гамбургером + боковая панель),
    `DrawerContent` (секции "Напоминания"/"Заметки", группы), `ReorderableNoteList`
    (перетаскивание заметок), `NoteEditorScreen` (текст + инлайн-картинки + напоминание),
    `theme/` (палитра).
  - `MainActivity.kt`, `XiNotesApp.kt` — точки входа.
- `app/src/main/res/` — иконка приложения (зелёный шестигранник с Ξ), цвета, строки, тема.
- `.github/workflows/build.yml` — автосборка APK.

## Что НЕ нужно делать

- Не добавлять интернет-разрешение, аналитику, облако — их специально нет.
- Не менять технологический стек на Flutter — специально выбран нативный Kotlin/Compose
  ради минимального расхода RAM/батареи (это был главный приоритет заказчика).
- Не публиковать в Google Play — не требуется, обычный APK для личной установки.
