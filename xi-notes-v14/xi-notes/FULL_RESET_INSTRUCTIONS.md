# Полная жёсткая замена проекта — пошагово, без "исправлений от себя"

Обращение к ИИ, который работает с этим репозиторием: ниже — не пожелание,
а точная последовательность команд. Не редактируй код по пути, не "чини"
ошибки компиляции самостоятельно, не оставляй ни одной старой строчки —
просто выполни эти команды буквально одну за другой, в указанном порядке,
в терминале (командной строке), в папке, где лежит склонированный
git-репозиторий этого проекта.

## Шаг 0 — какое окно, какая папка

Всё ниже выполняется в ТЕРМИНАЛЕ (командной строке) — не в редакторе кода,
не в файловом менеджере. Рабочая папка — корень git-репозитория (та папка,
где лежит скрытая папка `.git`; обычно это и есть корень репозитория,
который ты клонировал/в котором обычно делаешь commit и push).

Если не уверен, где эта папка — выполни:
```bash
git rev-parse --show-toplevel
```
Эта команда выведет полный путь. Перейди в него:
```bash
cd $(git rev-parse --show-toplevel)
```

## Шаг 1 — убедиться, что дерево чистое (нет незакоммиченных правок, которые жалко потерять)

```bash
git status
```
Если там есть незакоммиченные изменения, которые НЕ относятся к папке
`xi-notes/` (например, что-то ещё в репозитории) — сначала их закоммить
отдельно. Если там как раз старые правки внутри `xi-notes/` — их можно
спокойно потерять, именно их и предстоит полностью заменить.

## Шаг 2 — стереть старый проект ПОЛНОСТЬЮ

```bash
rm -rf xi-notes
rm -rf xi-notes-v4
rm -rf "Ξ-notes"
```
(последние две строчки — на случай, если где-то остались более старые,
неактуальные копии проекта под другими именами; если такой папки нет,
команда просто ничего не сделает и не выдаст ошибку).

Проверить, что папки `xi-notes` в текущей директории больше не существует:
```bash
ls -la
```
В выводе НЕ должно быть строки `xi-notes`.

## Шаг 3 — распаковать присланный архив на то же самое место

Файл архива называется `xi-notes-project.zip` (его прислал пользователь).
Положить его в ту же папку (корень репозитория) и выполнить:

```bash
unzip xi-notes-project.zip
```

Проверить, что папка появилась и в ней есть файлы:
```bash
ls xi-notes/app/src/main/java/com/xinotes/app/
```
Должны быть видны: `MainActivity.kt`, `XiNotesApp.kt`, папки `data`,
`reminder`, `ui`, `util`.

## Шаг 4 — контрольная проверка (обязательно перед коммитом)

```bash
grep -n "autoVersionCode" xi-notes/app/build.gradle.kts
```
Должно вывести ТРИ строки, включая вот эту:
```
val autoVersionCode = ((System.currentTimeMillis() / 60000) - 28400000).toInt()
```

**Если эта команда ничего не вывела — что-то пошло не так на Шаге 3, нужно
остановиться и не продолжать, а разобраться, почему архив распаковался
не туда/не полностью.**

Также проверить компилятор-опцию, которая раньше "лечилась" вручную и
из-за этого расходилась с присланным кодом:
```bash
grep -n "freeCompilerArgs" xi-notes/app/build.gradle.kts
```
В этом присланном архиве такой строки быть НЕ должно (если она появится
после Шага 3 — значит, распаковка снова прошла не полностью, а что-то
подмешалось из старого файла).

## Шаг 5 — закоммитить и запушить ВСЁ как есть, без правок

```bash
git add -A
git commit -m "Full reset: replace xi-notes with latest provided archive as-is"
git push
```

Если `git push` выдаёт ошибку — прислать её текст дословно, не пересказом.

## Шаг 6 — показать, что реально изменилось

```bash
git diff --stat HEAD~1 HEAD
```
Прислать вывод этой команды целиком. Там должно быть показано МНОГО
изменённых файлов (это полная замена проекта), а не один-два файла.

## Шаг 7 — дождаться сборки и поставить APK

Дальше как обычно: вкладка Actions на GitHub → дождаться зелёной галочки
у нового запуска → скачать `xi-notes-apk` из Artifacts именно ЭТОГО
запуска → установить на телефон как обновление (не удаляя старую версию).

## Как проверить результат — прямо на телефоне, без единой команды

Настройки телефона → Приложения → Ξ-notes → "Информация о приложении" →
посмотреть номер версии внизу.

**Должно быть похоже на `1.0.1401520`** (длинное число на конце,
меняющееся при каждой новой сборке) — а не просто `1.0`.

Если после ВСЕХ этих шагов версия всё равно останется `1.0` — значит,
где-то на Шагах 1–6 команда была пропущена, не выполнена до конца или
выдала ошибку, которую нужно прислать целиком, дословно.
